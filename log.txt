// REST FULL API : Rules for creating backend routes using HTTP methods.

> REST => Representational State Transfer

1-> REST API is a way for the frontend and backend to talk to each other using HTTP requests.

> It works on Server & Client Architecture. They both do not have to depend on each other.

> So we send data to client as a JSON that is key value pairs or a RAW DATA.
> If the client is browser like google.com then we send data as a HTML document & its fast.

2-> Always respect all http methods.
   GET POST PUT PATCH DELETE

> If the route is GET/USER -> It will read users data and return the data.

> If the route is POST/USER -> It will handle new user creation.

> If the route is PATCH/USER -> It will update the user.

> If the route is GET/getUSER -> Then it will be confusing. That's why we have to Respect all http methods.
